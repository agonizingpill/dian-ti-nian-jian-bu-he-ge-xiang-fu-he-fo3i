# lift-inspection-review

电梯年检不合格项复核工作台，服务南京景诚特种设备检测团队。应用把电梯档案、逐项检验、整改通知、复检证据和合格证签发串成一条可审计流程。

## 业务范围

- 操作员录入设备与检验项，失败项生成整改通知并预约复检。
- 主管审核复检结果并签发合格证，安全回路与制动器关键项一票否决。
- 复检证据必须使用原检验项编码，照片错配会被后端拒绝。
- worker 使用 `DecisionTreeClassifier(random_state=1066, max_depth=3)` 计算分流结果并导出规则路径。

## 分流推理复用

复核请求先归一化为四项分流输入（关键不合格数、平均分、不合格项数、资料缺失项数），
再取 SHA-256 指纹。**指纹相同即共用同一次树推理**，任何一项输入不同都会生成新的推理。

- 同一电梯重复点击复核、或操作员并发提交同输入复核单，只会挂到已有复核单，不新建任务。
- 同一指纹下的每张复核单仍有独立生命周期：`等待推理 / 已出结果 / 已撤回 / 失败`。
- 撤回只作用于那一张单：被撤回的单不再展示结论，同指纹的其他单照常领取建议。
- 推理完成后才提交的同输入复核单，直接复用已完成结果，不再触发新的树计算。
- worker 按推理任务加租约锁并定期心跳；进程中断后租约到期自动续跑，重复执行时只向仍
  处于等待态的单发放建议，已出建议的单不会重复发送。
- 工作台「检验复核」页展示该设备每张复核单的状态、输入指纹、建议与共享单数，并可撤回。

相关接口：`POST /api/lifts/{id}/review`、`GET /api/analysis/jobs`、
`GET /api/analysis/inferences`、`POST /api/analysis/jobs/{id}/withdraw`、
`POST /api/analysis/inferences/{id}/retry`。

## 启动

```bash
docker compose up -d --build
docker compose exec -T backend python scripts/seed_demo.py
```

访问 `http://localhost:18265`。后端健康检查在 `http://localhost:19265/api/health`。


## 业务核验模块

登录后打开页面右下角的「业务核验」。可从实时业务台账筛选记录、导出所选结果，主管可对当前证据签认并填写说明。

- **年检到期排程** 按年检到期日排序并标出近 30 天到期与逾期资产，供检验员安排路线。
- **关键项整改督办** 聚合关键不合格项及整改资料，未开单、过期或缺复检记录可分别交接。
- **证书有效性对照** 对照证书有效期与资产仍未验证的关键缺陷，保留主管判断依据。

### 二次扩展核验

- **复检影像归属核验** 把复检照片与原不合格项编号逐一对照，识别缺影像和串项证据。
- **复检员同档排班冲突** 按复检员与相同预约时点核对尚未完成的排班，重约或关闭后自动释放冲突。

## 业务处置与验收

登录后打开「复检补证与改约」。操作员提交结果、凭证号和说明，主管可复核关闭或退回补证，观察员可查看记录。关闭时复查源业务状态，处置历史保留每次操作。

- 串项影像补证验收
- 同档复检改约验收
